# 框架 × 底模矩阵评测规划(AA 式)(2026-07-03)

> 用户提案:对评分高的框架,各跑多个 LLM 底模,像 Artificial Analysis
> 那样呈现。本文档 = 为什么值得、怎么设计、预算多少、怎么呈现、和论文
> 的关系。执行顺序上排在 v2 全量首跑(todo #39)之后。

---

## 1. 为什么值得做(三重收益)

1. **补论文因果缺口(最重要)**。当前 §5 的诚实表述是:"底模榜的分数差异
   *associated with* 底模,因果归因需要把底模随机交叉到脚手架上,我们没做。"
   框架 × 底模全交叉设计正是这个实验:做完即可把"关联"升级为
   "在所测框架与底模范围内的因果分解"(框架主效应 / 底模主效应 / 交互项)。
2. **回答实践者真正的问题**:"我该换框架还是换模型?" 单维榜答不了;
   矩阵直接给出:哪个框架对底模敏感(换模型收益大),哪个框架稳健
   (差模型也不崩),哪个格子是性价比最优组合。
3. **站点差异化**:AA 有模型矩阵没有 agent 框架矩阵;deep-research 框架
   × 底模 × 可判定真值分,是别家没有的图。

## 3. 预算与调度(单卡现实)

- 一次只能服务一个模型 ⇒ **按底模分批**:装载模型 → 跑完该列全部
  框架×任务 → 换下一个模型(vLLM 重启 ~2-5 分钟,模型在 9P 上加载慢,
  换载次数压到 M-1=3 次)。
- 时间估算(试点实测后修正):8B/14B 单跑 ~3-6 分钟,27B eager ~8-15 分钟。
  120 新跑次 ≈ 8B/14B 列 80 次 × 5min + 27B 复用 + llama 列 40 次 × 5min
  ≈ **10-14 小时纯跑**,加重试与换载 ≈ 1-2 个通宵,GPU 静音配置不变
  (400W/1500MHz,风扇 30% 档)。
- 断点续跑:沿用试点驱动的 `>3KB 才算成` 检查点;每列一个 tmux 批任务。
- 判官/panel 不占矩阵时间:presentation 列后补(等重判基建),truth 五轴
  纯离线可评,**矩阵榜第一版只发 truth 五轴,无 LLM 判官依赖**。

## 4. 统计口径(下笔前定死,防事后挑数)

- 每格 = 10 题 truth 的 macro 均值 + min_report_truth;格间比较用
  两层 bootstrap(题目重采样)95% CI。
- **双因素分解**:truth ~ 框架 + 底模 + 交互;报告三者的方差占比
  (η²);n 小,定位为**效应量描述而非显著性检验**(诚实纪律延续)。
- **底模敏感度**(站点新指标):同一框架跨底模的 truth 极差 / 均值;
  低敏感 = 脚手架稳健,高敏感 = 收益主要来自模型。
- **成本轴(2026-07-04 用户拍板新增)**:每格同时报整次运行 token 合计
  (prompt+completion,经 ds_proxy 记账,流式含 usage 注入)与折价
  (data/model_prices.json,只用有来源的单价;本地模型价未验证前只报
  token)。派生指标:truth-per-Mtok 与 AA 式 truth×成本散点。采集与聚合
  见 scripts/aggregate_run_costs.py 与 PILOT 交接文档 §5b——**开跑前必须
  部署,数据无法事后补采**。
- 预注册在本文档:主指标 truth_macro,任务子集与底模池以上文为准,
  跑完不加格子不删格子;失败格(框架×底模不兼容)如实标注不填补。
