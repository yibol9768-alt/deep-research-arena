## 二、本周具体做了什么(按时间线)

### 1) 锁定打分方法学:真值门控 Elo(6-05)
- 确定并锁死了全站默认排序口径:**headline = 判官 Elo × 接地门**。
  - 公式:`gated_score = round(elo × (reachability% + quote%) / 200)`。
  - 每个 agent 都打分、都上榜,不做"剔除";接地信号以独立列展示,让"判官打高分但引用打不开"的背离一眼可见。
  - 设计动机:一个写得流畅但引用不可达的 agent **永远无法登顶**,杜绝靠文笔刷榜。
- 裸判官 Elo 单独做成森林图(forest plot)展示,真实的置信区间分离可见。
- 同步做了一次全站"去水分"巡检:换成真实 backbone、真实信号,删掉过时口径声明。

### 2) 判官修复:静默 error-to-TIE bug + 真三判官(6-06)
- **发现并修复一个严重 bug**:判官调用出错时被静默计为"平局(TIE)",导致平局率虚高(51%)。
- 上线真正的 **3 判官陪审团(PoLL)**:deepseek-v4-flash + qwen3-max + glm-5,多数票、位置去偏、Bradley-Terry + bootstrap 置信区间。
- 全部 **1,553 场对战重新评分**;修复后平局率从 51% 降到 **17%**(1,553 场全部三判官投票)。
- 校正了陪审"降级判定"逻辑:**2/3 一致就是合法 PoLL 结论**,停止无意义的反复重判。
- 方法学页面同步更新(之前还写着"单判官",已改成三判官描述)。
- 经验记入:验证陪审要按"干净计数"而非"对战计数"。

### 3) 评测集体检与清洗(贯穿本周)
- 对自动构建的 golden(must-cite)做体检:发现 **62% 是关键词碰撞的离题垃圾**,已剔除。
- 给每个任务补了 `valid_sources` 限源清单。
- 100 个 deep 任务体检结果:**75 个可评 + 25 个隔离**(详见 `docs/EVAL_SET_REMEDIATION.md`)。
- 确认接地门(truth-gate)是**判官无关**的,能独立把"编造引用"的 agent 拦下。
- 区分力分析(8-agent 工作流):剔掉死信号(claim_nli 全 0)和注水信号(字数/引用数),确认 **reachability + 长度归一化 presentation** 是仅有的合法可区分信号;同时诚实指出顶部几个能干的 agent 是真的接近,且 box 打分覆盖不均。

### 4) 沙箱抢救(6-07 前后)
- WSL 重启把 DRA 沙箱容器整组冲掉(容器被移除而非停止,`docker start` 拉不回来)。

- 修复 WSL interop(`cmd.exe: Exec format error`),写了 docker-free 的应急恢复路径,运维经验记入 memory(`my5090-sandbox-recovery`、`my5090-detached-proc-kill`)。

### 5) 判官欠费 → 改做"不依赖 API"的版本

  - 通过 `build_sandbox_cache.py`(整库爬一次)+ `score_grounding_from_cache.py` 实现,完全不碰判官 API。

## 五、确定的部署链路(已记入 memory `dra-site-deploy`)

生产 app = `frontend/`(Next.js 14 静态导出),**不是** `web-next/`。

1. 改 `frontend/` 源码 + `data/results/deep_v3/` 数据。
2. 追加 `data/changelog.json` 条目(硬规则,否则 /changelog 页面会撒谎)。
3. `cd frontend && npm run typecheck && npm run build` → `frontend/out`。
4. `rsync -a --delete --exclude 'wrangler.jsonc' frontend/out/ web/dist/`。
5. 提交源码 / 数据 + 重建后的 `web/dist/`(Cloudflare 实际服务的就是这个已提交产物)。
6. **从这台工作机** `git push origin HEAD:main`,Cloudflare 约 2-5 分钟自动重建。

三个仓库的分工:box `/opt/deep_reserch`(评测,非 git)、box `/mnt/d/lyb/deep_reserch`(站点 git,但连不上 github)、**本工作机 `/root/Desktop/lyb/deep_reserch`(有外网,从这里 push)**。

## 六、未来规划

总方向(用户本周已确认):**不再做 RL/GRPO 那一套,只把 DeepResearchArena 做成一个真正好的 Deep-Research 评测数据集。** 目标产物 = 约 120 个任务、跨家可复现、接地可验证、打分诚实且能区分、且有人类对齐证据的基准 + 一个真实线上排行榜。

> 最大风险仍是 **box 不稳**(WSL 会重启、隧道会抖、和 course-kg 共用),所以稳定化是前置,且所有长任务要可断点续跑 + 即时落盘 + 自愈,最终把分数 cache 进仓库做到离线可复现。

### Phase 0(前置)沙箱稳定化
- 用统一 compose `infra/sandbox.docker-compose.yml` 一条命令拉全栈,加 `restart: unless-stopped`。
- box 端 tmux + 外侧重连监工自愈;`wsl --shutdown` 后能自动恢复到 200。

### Phase 1 语料扩展 + 重爬受影响任务 golden
- 给论坛(Postmill)种入非技术主题帖(财经/健康/环境/教育/政策/旅行),让 25 隔离 + 10 forum-invalid 任务重获论坛维度。
- seed SQL 做成幂等并**提交进仓库**(`reset.sh` 后不丢);重爬这些任务的 on-topic golden,scorable 从 75 升向 ~100。

### Phase 2 给 22 个对抗任务构建 golden
- `cross_site_deep_v2/`(causal_debunking / contradiction / long_tail 等共 22)目前只有 seed,给它们爬真 golden 并纳入基准,任务总数升到约 122。

### Phase 3 全场统一打分 + 分数 cache 进仓库
- 先修打分吞吐(降并发,避免把 Magento 打到 reset 触发 60% FAIL)。
- 全部 ~122 任务 × 所有 agent 在稳定沙箱上统一重打分,canonical 分数**提交进仓库**,让基准离线可复现。

### Phase 4 锁定打分方法学(门 + 可区分复合分)
- 在统一富信号上重跑区分力分析,选定最终复合分(起点 `0.75×reachability + 0.25×presentation_lenadj`)。
- 校准门槛 floor 落在"能干簇 vs 失败簇"的自然间隙;跑全套 anti-hack 断言(堆字数/堆引用不能刷分,编造者被拦)。

### Phase 5 人类对齐(可信度锚)
- 用已上线的 `/annotate` 收成对人类偏好;算 judge-vs-human 的 Cohen's kappa 与排名相关性,写进 `EVAL_FACTSHEET.md`。
- **依赖真人标注者**(用户本人或指定几位),管线我已准备好。

### Phase 6 重算排行榜上线 + 定稿文档
- 用干净统一分数重算并部署;定稿 `DATASHEET.md` / `EVAL_FACTSHEET.md` / benchmark README,诚实标注覆盖与局限。
